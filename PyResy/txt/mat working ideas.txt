# Resiris `mat` — Working Specification
# STATUS: CURRENT / READY FOR IMPLEMENTATION

## 1. What is the "mat" statement?
`mat` is a control-flow statement which compares a given value against multiple possible cases.

`mat` is NOT a function, module, or runtime API. It is built-in Resiris language syntax/control-flow.

## 2. Basic syntax
    mat variant_name:
        case_value:
            code
        case_value:
            code
        else:
            code

The value checked by `mat` must be a previously existing variant/value. A literal cannot be used directly as the value checked by `mat`.

Type matching can be requested with `.type()`:
    mat variant_name.type():
        int:
            print_cmd("Is int")
        float:
            print_cmd("Is float")

A `.string()` result can also be used as the value being checked.

## 3. Value checked by `mat`
The checked value may be:
- int
- float
- string
- bool
- ModuleObject
- any other defined Resiris type

UnknownObject cannot be used as the checked value.

A literal cannot be used directly as the checked value.

`.type()` and `.string()` may be used to produce the value being checked.

No other function can be called with dot syntax except the built-in `.string()` and `.type()` functions.

## 4. Case values
Cases use concrete, fixed values.

Supported case values include int, float, string and bool.

A case cannot contain an expression.

A case cannot use a variable or constant in place of its concrete value.

## 5. Case type rules
All cases in one `mat` use one type.

Different case types cannot be mixed in the same `mat`.

Type matching uses exact type equality.

If a case has a different type from the checked value, that case is skipped.

## 6. Matching behavior
The value checked by `mat` is evaluated exactly once.

The resulting value is compared against the case values.

Case order does not affect the result.

When a case matches:
1. Its branch executes.
2. Every statement in that branch executes.
3. The `mat` ends.
4. Execution continues with the next statement after the `mat`.

There is no fall-through.

If no case matches:
- with `else`: the `else` branch executes;
- without `else`: execution continues after the `mat`.

## 7. Else
`else` is optional and must be the last branch.

Only one `else` is allowed.

A `mat` cannot contain only an `else`; at least one case is required.

An `else` branch may contain multiple statements.

## 8. Branch bodies
A case may contain multiple lines of code. Every statement in the matched case executes.

`return` may be used inside a `mat` case.

`pass` may be used inside a `mat` case.

A matched case does not automatically terminate the surrounding function. After `mat`, execution continues after the complete `mat`, unless `return` changes the surrounding function's control flow.

## 9. Nesting and valid locations
`mat` may be used:
- inside functions
- inside `start()`
- inside `process(delta)`
- inside `if`
- inside `elif`
- inside `else`
- inside other valid Resiris blocks

A `mat` may NOT be nested inside another `mat` case.

Error:
"{case} Cannot call match inside a match function. Error code:"NestedMatchError"

## 10. Errors
Missing checked value:
"{given value/variant} does not exits! Error code:"NonExisistigValue"

Invalid case value:
"{given case value} is an invalid case value. Error code:"InvalidCaseValue"

Invalid `mat` syntax:
"mat statement has invalid syntax. Error code:"InvalidMatchSyntax"

Invalid indentation:
"invalid indentation in mat case. Error code:"InvalidIndentation"

Case without body:
"case has no body. Error code:"MissingCaseBody"

Empty `mat` body:
"mat statement has an empty body. Error code:"EmptyMatchBody"

Execution error in matching case:
"{error} occurred while executing the matching case. Error code:"MatchCaseExecutionError""

The matching case stops executing, and the error propagates to the surrounding `mat` statement and function.

## 11. Duplicate cases
The same case value cannot appear more than once.

Error:
"{the duplicate case} is already a used case value!" Error code:"SameCaseMultiCall"

## 12. Example
    mat value:
        1:
            print_cmd("one")
        2:
            print_cmd("two")
        else:
            print_cmd("other")

## 13. Implementation status
`mat` is considered a completed Resiris language feature specification.

This document is the authoritative working specification for implementing `mat`.

Implementation must follow this document and must NOT invent additional `mat` behavior.

If an implementation detail is not covered here, it must be treated as undefined rather than silently adding a new language rule.
