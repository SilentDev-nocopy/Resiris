include command: <include> RSNetwork

Its purpose and usage is to make servers or webpages served locally and also to access the web using Wi-Fi.


network stuff: EspOnly

	constants:
		ROUTEMODE = "connect_to_existing_router, -> ESP 'station (STA)' mode -> short: CXE
					self_router, -> ESP 'access point (AP)' mode -> short: SR
					man_in_between, -> ESP 'dual mode (STA+AP)' -> short: MB"


	functions:
		RSNetwork.wifi() -> main function for every Wi-Fi oriented script.
		RSNetwork.wifi().get_all_networks() -> gives back every Wi-Fi network name (SSID) as string.
		RSNetwork.wifi().connect(SSID, password) ->connect to the given network with the password
		RSNetwork.wifi().set_route_mode()






hosting a website/server: EspAndPc

	The main goal is for the hosting hardware to have as little work to do as possible! That's why we don't use JavaScript or CSS on the hosting side! Let's leave the heavy computation to the client!
	It runs only HTML. No JavaScript or CSS! The client can use JavaScript, CSS and others.


	functions:
		html_server_handler() -> main function for the usage of HTML servers. Without it, the server can't exist because it will miss the handler!
		create_server(port_number as int) -> creates the server by its handler.
		set_page_content(file_path or a string type variable) -> sets the server front page HTML file. #file path is currently not available! maybe in later version!
		set_client_script(js string) -> sets the JavaScript served at /rsclient.js. Call it before start_server(). If it is not set, /rsclient.js returns an empty response.
		start_server() -> starts the server so it can be accessed by entering the hardware's IP address in a browser. If create_server() has not been called, display: "Error: Server not initialized. Call create_server(port_number) before start_server()."
		process() -> accepts one new request and sends the buffered response on the next call.

		request_string_data()
			Returns the most recent string data received since the last process() call.
			Repeated calls return the same most recent data until a new request arrives.
			Throws "RSNetwork.request_string_data: no most recent string data" if none.

		request_int_data()
			Returns the most recent int data received since the last process() call.
			Repeated calls return the same most recent data until a new request arrives.
			Throws "RSNetwork.request_int_data: no most recent int data" if none.

		request_float_data()
			Returns the most recent float data received since the last process() call.
			Repeated calls return the same most recent data until a new request arrives.
			Throws "RSNetwork.request_float_data: no most recent float data" if none.

		request_boolean_data()
			Returns the most recent bool data received since the last process() call.
			Repeated calls return the same most recent data until a new request arrives.
			Throws "RSNetwork.request_boolean_data: no most recent bool data" if none.

		get_request_state()
			True only while the most recent data is unread.

		respond_string_data(value string)
			Buffers a string response for the most recent request; the next process() call sends it.
			A later respond overwrites the buffered response.

		respond_int_data(value int)
			Buffers an int response for the most recent request; the next process() call sends it.
			A later respond overwrites the buffered response.

		respond_float_data(value float)
			Buffers a float response for the most recent request; the next process() call sends it.
			A later respond overwrites the buffered response.

		respond_boolean_data(value bool)
			Buffers a bool response for the most recent request; the next process() call sends it.
			A later respond overwrites the buffered response.

		##Each function throws an error if no request is currently awaiting a response.

	open questions:
		- What URL should the browser call? For example: /call/add/2/3, /call/add?a=2&b=3, or a JSON body?
			Browser requests use URL query parameters, for example /call/add?value=5. Only the most recent data from the most recent request is kept.
		- Can the server keep several requests waiting?
			only one at a time.
		- If the browser sends 2 and 3, do two request_int_data() calls return 2 then 3, or does each getter read a different typed field of the same request?
			The most recent data wins. Repeated calls to the same request function still return that most recent data.
		- What text should the browser receive for each response type? For example: true -> "true", 5 -> "5", 1.5 -> "1.5".
			true -> "true", 5 -> "5", 1.5 -> "1.5"
		- If respond_*_data() is called twice for one request, is the first answer kept, the last answer sent, or is it an error?
			always the most recent.
		- Should get_request_state() be true only while data is unread, or also after the data is read but before respond() is called?
			only while the most recent data is unread. After it is read, the response is sent on the next frame.

	client script:

		The script is given to the module with set_client_script(js string) and served at /rsclient.js.
		One script is enough for every page; it does not have to be written into each HTML page.
		The page only declares which button calls which name.

		HTML in the page:

			<input id="num" value="5">

			<button rs-call="add" rs-value-from="#num" rs-target="#out">
				Send
			</button>

			<output id="out">...</output>

			<script src="/rsclient.js"></script>

		rsclient.js:

			(() => {
				function readValue(el) {
					const from = el.getAttribute("rs-value-from");
					if (from) {
						const source = document.querySelector(from);
						return source ? source.value : "";
					}
					return el.getAttribute("rs-value") || "";
				}

				async function callElement(el) {
					const name = el.getAttribute("rs-call");
					const targetSelector = el.getAttribute("rs-target");
					const target = targetSelector ? document.querySelector(targetSelector) : null;

					if (!name) return;

					const value = readValue(el);
					const url = "/call/" + encodeURIComponent(name) +
						"?value=" + encodeURIComponent(value);

					try {
						const response = await fetch(url);
						const text = await response.text();
						if (target) target.textContent = text;
					} catch (error) {
						if (target) target.textContent = "Error: " + error.message;
					}
				}

				document.querySelectorAll("[rs-call]").forEach(el => {
					el.addEventListener("click", () => callElement(el));
				});
			})();

	Usage:
	<include> RSNetwork

	c FPS float = 10.0
	v page ModuleObject = RSNetwork.html_server_handler()
	c port_number int = 8080
	c rsclient_js string = "..." ## the rsclient.js script from the client script section
	v html_page_content string = "<!DOCTYPE html> <html><head><title>My Page</title></head><body><input id='num' value='5'><button rs-call='add' rs-value-from='#num' rs-target='#out'>Send</button><output id='out'>...</output><script src='/rsclient.js'></script></body></html>"

	START():
		page.create_server(port_number)
		page.set_page_content(html_page_content)
		page.set_client_script(rsclient_js)
		page.start_server()

	PROCESS(FPS):
		page.process()
		if page.get_request_state():
			v data_from_page int = page.request_int_data()
			page.respond_string_data("ok")
