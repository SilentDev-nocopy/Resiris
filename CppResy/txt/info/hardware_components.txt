Custom Calculator – Components

The goal is a custom, programmable scientific calculator, mainly for school and home use.

STATUS: CONCEPT AND PROCUREMENT PLAN

This is a list of proposed components, not confirmation that they have been
purchased, assembled, or integrated. Check the exact product variant, current
availability, and electrical specifications before purchase or wiring.

1. ESP32-WROOM-32

CPU: Xtensa LX6; the classic ESP32-WROOM-32 is dual-core and can run
     up to 240 MHz. Confirm the selected board variant.
RAM: approximately 520 KB internal SRAM on the chip; less is available
     to the application as heap.
Flash: board-dependent; 4 MB is common, not guaranteed by the module name.
Wi-Fi: 2.4 GHz
Bluetooth: Classic + BLE
GPIO: 34 GPIO-capable signals are associated with the ESP32 chip; the
      WROOM-32 module exposes a subset. See `esp32_gpio_table.txt` for
      the project's selected 26-pin map and limitations.
ADC: 12-bit
Communication: UART, SPI, I²C
Power: 3.3 V for the chip
Development board: programmable via USB

Planned controller. No keyboard matrix, display driver, battery manager, or
custom program storage is documented here as implemented.

2. OLED Display

Type: OLED
Size: 2.42"
Resolution: 128 × 64 pixels
Color: monochrome
Controller: SSD1309
Communication: I²C / SPI
Power: 3.3–5 V
Touch: none
Dimensions: approx. 71 × 43.5 mm

The interface must be confirmed for the selected display variant; I2C is a
candidate, not an implemented connection.

3. Keyboard

Switches: tactile push button
Legs: 4
Design: Through-Hole (THT)
Size: 12 × 12 mm variants
Kit: 250 pcs, various sizes/heights
Planned number of buttons: approximately 40–50; not yet wired or validated
Wiring: button matrix

The buttons will provide access to basic operations and scientific functions, such as sin, cos, tan, log, ln, square root, power, parentheses, etc.

4. Communication and Data Transfer

PC <-> calculator: USB is intended for firmware upload and debugging. A
custom calculator data-transfer protocol is a future idea, not implemented.

Transferring programs: A custom program format, USB transfer tool, and
persistent user-program storage have not been implemented.

Possible system:
PC → USB → ESP32 → Flash memory
PC → USB → ESP32 → loading/running a program

Later, we can create a custom PC program in which the calculator's programs can be written, edited, uploaded, and deleted.

ESP32 and display: I²C or SPI connection.

ESP32 and keyboard: via GPIOs, using matrix wiring.

5. Programming

Firmware: C/C++
Development: VS Code + PlatformIO
Planned firmware responsibilities: computation engine, keyboard, display,
memory, menu system, and program management. These integrations are not
implemented in this CppResy desktop CLI.

The Resiris C++ interpreter exists as a desktop CLI in this repository.
Calculator firmware integration, display UI, and persistent user-program
management are not implemented by this component plan.

6. Power Supply

Not yet selected. We will first build and measure the prototype's power consumption, then choose the battery or other power supply accordingly.
